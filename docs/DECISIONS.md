# JSeek 关键决策（ADR）

> D-001 至 D-005 起草于 JMacEverything 仓库 `v2` 分支，随方案一起迁入。

每条决策：编号、日期、结论、原因、放弃的方案。改变决策时新增一条，不改旧条目。

## D-001 保留 C++ 引擎，经 FFI 由 Rust 调用（2026-10-24）
- **结论**：2.0 不重写搜索引擎；先把 C++ 引擎的 GCD/CoreFoundation 依赖换成跨平台实现，再用 `cxx` 桥接给 Rust。
- **原因**：引擎约 9,200 行、11,962 个测试全过，是产品速度的来源；重写风险高、周期长，而跨平台真正缺的只是扫描层和界面。
- **放弃**：纯 Rust 重写（可作为 3.0 方向，逐模块替换）。

## D-002 界面用 Tauri 2 + Vue 3（2026-10-24）
- **结论**：一套前端覆盖 Mac 和 Windows。
- **原因**：与系列产品技术栈一致；安装包小；Rust 端可直接复用核心。
- **放弃**：各平台原生界面（SwiftUI + WinUI，两份 UI 代码）；Electron（体积和内存大）。

## D-003 Windows 用只读索引服务读取 MFT/USN（2026-10-24，待确认）
- **结论**：安装时注册 `jme-indexer` 服务（只读），GUI 保持普通用户；无服务时降级为目录遍历。
- **原因**：MFT/USN 是 Windows 上秒级索引的唯一途径，且需要管理员权限；把特权限制在最小的只读组件里。
- **放弃**：让 GUI 以管理员运行（风险大、每次弹 UAC）。

## D-004 开发过程的数据保护（2026-10-24）
- **结论**：所有工作在 GitHub `v2` 分支上进行；每完成一个可描述的步骤就提交并推送；进度写入 PROGRESS.md；用 `scripts/checkpoint.sh` 统一完成「记录 + 提交 + 推送 + 校验远端」。
- **原因**：会话可能中断、本地机器可能不可用；以 GitHub 为唯一可信存档，任何时刻丢失的工作不超过一个步骤。

## D-005 确认 Windows 只读索引服务（2026-10-24）
- **结论**：用户确认接受「安装时请求一次管理员权限，换来秒级索引」，D-003 由「待确认」转为已定。
- **影响**：M4 按 MFT + USN + `jme-indexer` 服务实现；无服务的遍历模式保留为降级路径。

## D-006 新仓库与产品名（2026-10-24）
- **结论**：跨平台版独立为新产品 **JSeek（简搜）**，仓库 `luckySpro/Jseek`；JMacEverything 1.x 继续维护到 JSeek 可替代为止。
- **原因**：跨平台后不再是 Mac 专属；`SearchEverything` 已有同名产品且含 voidtools 的产品名；JSeek 延续 J 系列、简短、搜索未见同名软件。
- **分支**：`main` 只放稳定内容；日常开发在 `dev`，checkpoint 脚本拒绝在 `main` 上运行。

## D-007 Windows 安装包的发布者名（2026-10-24）
- **结论**：NSIS（EXE）使用原名「M&J Group」；MSI 通过 `app/src-tauri/tauri.msi.conf.json` 单独覆盖为 `M&amp;J Group`，CI 中分两次构建。
- **原因**：WiX 把发布者当 XML 解析，`&` 未转义会报 CNDL0104；内联 JSON 参数在 Windows cmd 中会被 `&` 截断，所以用配置文件。
- **放弃**：全局把发布者写成转义形式（会污染 EXE 的真实公司名）。

## D-008 Rust 与 C++ 引擎之间用纯 C 接口（2026-10-25）
- **结论**：桥接层为 `engine/Bridge/jseek_c.h`（纯 C ABI），Rust 侧 `crates/jseek-engine` 做安全封装并提供 `jseek` 命令行；build.rs 直接调用 CMake 与 pkg-config 构建、链接引擎。
- **原因**：接口只有扫描/加载/保存/搜索几个函数，C ABI 足够；不引入 cxx/cc/cmake 等构建依赖，三平台行为一致，锁文件不变动。
- **放弃**：计划中的 cxx（对这么小的接口收益不大，且多一层代码生成）。
